# Gromnie iOS app

A minimal SwiftUI iPhone/iPad client whose only gameplay capability is chat.
Rust retains all protocol parsing, transport, and cryptography; SwiftUI owns
presentation, input, lifecycle, and secure preferences.

## Layout

- `project.yml` — XcodeGen source of truth for `Gromnie.xcodeproj` (generated, not committed).
- `Sources/GromnieKit` — Swift wrapper over the `GromnieCore` C module. All C calls run on one serial queue and events are surfaced as an `AsyncStream<BridgeEvent>`. The app never imports the C header.
- `Sources/Gromnie` — SwiftUI app: three screens (`ConnectionView`, `CharacterListView`, `ChatView`), `SessionViewModel`, and Keychain/UserDefaults preferences.
- `Frameworks/GromnieCore.xcframework` — generated (gitignored).

## Prerequisites

```bash
rustup target add aarch64-apple-ios aarch64-apple-ios-sim x86_64-apple-ios
cargo install cbindgen
brew install xcodegen
```

Make sure the full Xcode app is active:

```bash
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
```

## Build the Rust core

```bash
cargo xtask ios build-core
```

This regenerates the C header (failing if it drifts from the committed copy)
and writes `ios/Gromnie/Frameworks/GromnieCore.xcframework`. If `xcodebuild` is
not on the active developer directory, prefix with `DEVELOPER_DIR=...`.

## Generate and build the app

```bash
cd ios/Gromnie
xcodegen generate
xcodebuild -project Gromnie.xcodeproj -scheme Gromnie \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO build
```

`Gromnie.xcodeproj` and the `Support/*/Info.plist` files are generated by
XcodeGen and are not committed. Re-run `xcodegen generate` after editing
`project.yml` or adding/removing source files.

## Running tests

No iOS simulator runtime is installed by default on this machine. Install one
before running `xcodebuild test`:

```bash
xcodebuild -downloadPlatform iOS
```
